# Полный обход (inventory / cutover / «везде»)

Срабатывает, если пользователь просит смыслы вроде: **обойти весь код / все запросы / везде / полный cutover / все URL / всё проверь / inventory**.

Пользователь **не обязан** знать список. Составить реестр и проверить — **работа агента**.

## Запрещено

- Чинить только то, что «ткнули» / светилось в логе, и закрыть задачу.
- Писать «готово / работает / cutover ок / в основном всё» без таблицы по **всем** найденным пунктам.
- Фразы «скорее всего / должно работать» вместо статуса пункта.

## DoD (порядок жёсткий)

1. **Реестр** — полный список находок (файл → что/куда бьёт). Правки **ещё нет**. В ответе: «найдено **N**».
2. **Проверка** — каждый из N: ок / сломан / ещё старый хост / не на нашем бэкенде.
3. **Правки** — по реестру, не выборочно «сначала очевидное и стоп».
4. **Verify** — повторный поиск: старых целей **0**, либо явный список **осознанных** исключений с причиной.
5. Закрытие только если N пройдены и verify сделан. Иначе: «осталось M из N», не «готово».

## Примеры применения к Cab Drive

- Cutover на Postgres: все прямые write/read Firestore в МП.
- URL/API: все вызовы `ydrive.appwave.com`, `37.252.20.248:5000/kek`, старые Cloud Functions.
- Секреты: все `your-*`, `TODO`, `changeme` в коде.
- Карты: остатки `google_maps_flutter` / `FlutterFlowGoogleMap`.

## Якорь (желательно в конце задачи)

`полный обход, реестр N, verify 0, без «готово» раньше`
