# Не ломать работающие флоу

## Жёстко

- После правок **не считать задачу закрытой**, пока не проверен **старый критичный путь**:
  - вход в админку (`/d/auth` → страница после логина);
  - ключевые экраны МП (карта/оплата), если трогали сервер/клиент рядом.
- Логин «status=ok» без успешного открытия следующей страницы = **баг**.
- Страницы админки после логина **не должны** зависеть от тяжёлого Firestore stream без soft-fail.
- При `ResourceExhausted` / timeout Firestore: **пустые данные / сообщение**, не падение worker и не nginx **504**.
- Не редиректить логин на `/d/statistics` / `/d/`, пока эти страницы гоняют полный `order.stream()` (сейчас после логина — `/d/order_settings`).

## Перед деплоем сервера

- [ ] `curl` `/d/auth` → 200 быстро.
- [ ] POST логин → ok.
- [ ] GET целевой страницы после логина → не 504 (таймаут < 10с).
- [ ] journalctl: нет каскада worker SIGKILL на админ-роутах.

## Прод app-data = Postgres

- Новые app-данные пишем **только в Postgres**.
- Firestore — только soft mirror при `APP_FS_MIRROR=1`; на проде **0**.
- МП: не читать/писать Firestore как SoT; API/WSS only.
- Не путать MySQL `cab` (админка) и Postgres `app_*` (приложение).
