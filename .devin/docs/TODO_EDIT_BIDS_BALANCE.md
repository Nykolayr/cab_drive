- Роуты: `server/app_data/__init__.py` — `POST /orders/<id>/bids`, `DELETE /orders/<id>/bids/<bid_id>`; `PATCH` нет.
- PG: `server/app_pg.py` — `create_order_response`, `delete_order_response`, `list_order_responses`; `update_order_response` надо добавить.
- FS-зеркало: `app_fs_mirror.soft_fs` — обновление `responses/<bid_id>` в Firestore.
- Клиент: водитель видит свой отклик на `order_page_driver` (есть «Отменить отклик» → `otmena_otklika`). Нужна кнопка «Изменить» → `create_otklick` с предзаполненными комментарием/временем → PATCH.

**Что делать (сервер):**

- Роут `PATCH /orders/<order_id>/bids/<bid_id>` в `app_data/__init__.py`.
- FS-зеркало: `order_ref.collection('responses').document(bid_id).update({...})`.

**Что делать (клиент):**

## П.5 — Пополнение баланса «только картой»

**Текущее состояние:**
- `lib/driver/popolnit_balans/popolnit_balans_widget.dart` → `PayBalanceWidget`:
  `InitPaymentCall` → наш `POST /api/tinkoff/init-payment` (`server/tinkoff/urls.py` → `tinkoff/client.py init_payment`) → банк отдаёт `paymentUrl` → `FlutterFlowWebView` открывает **хостинг-форму Тинькофф** внутри приложения.
- В приложении выбора способа оплаты нет — СБП/T-Pay/карта живут внутри формы банка.
- Проверка прода (tinkoff_events.jsonl, tinkoff_notify.log): все успешные платежи — карта (`Pan`/`CardId`), **ни одной попытки СБП**; единственные отказы — `REJECTED` ErrorCode 1042.
- Webhook (`server/tinkoff/webhook.py`) универсален по способу оплаты: смотрит только `Status` (CONFIRMED/AUTHORIZED) + `PaymentId` + `Token` → **СБП-платёж зачислится без изменений кода**, если банк его пропустит.

**Причина «СБП не работает» (по гайду `_my_template/docs/tbank-integration-guide.md` §3.6):**
способы оплаты на хостинг-форме настраиваются в **ЛК Т‑Бизнес**:
`business.tbank.ru` → Магазины → магазин → «Приём оплаты» → «Настроить» готовую платёжную форму → тумблеры «Банковская карта»/СБП/T‑Pay.
На нашем терминале (`1738251299121`) СБП не включён → кнопки нет/оплата падает на стороне банка до webhook.
T‑Pay из ЛК не отключается (только через поддержку или своя форма GetQr).

**Что делать:**
1. **Правильный фикс (без релиза):** в ЛК Т‑Бизнес на терминале выключить СБП на платёжной форме — тогда заказчик видит только карту. Делает владелец ЛК, не код.
2. **В приложении (пояснение):** на экране `popolnit_balans` добавить подпись «Пополнение только банковской картой. Оплата через СБП не поддерживается».

**Если заказчик наоборот захочет включить СБП:**
- вариант A (кнопка СБП на форме банка): включить тумблер в ЛК — 0 строк кода, webhook сам зачислит;
- вариант B (свой QR в приложении, без формы банка): `Init` + `GetQr` → отдельный endpoint + экран QR/деeplink — средняя фича.

## П.6 — Поиск адреса «Ничего не найдено» (баг, подтверждён)

**Симптом заказчика:** поиск «1 дубровская ул 14/1» → «Ничего не найдено»; жалоба на отсутствие кнопки «Указать на карте».

**Диагноз (проверено):**
- Yandex Geosuggest/Geocoder и Google Places отвечают 200 с результатами — провайдеры и ключи живы.
- Результаты отсекает клиентский фильтр `_titleMatchesQuery` в `lib/custom_code/services/yandex_geocoder_service.dart` (~строки 181-200): весь нормализованный запрос должен быть подстрокой title/street, либо `house` буквально входить в запрос.
- Форматы не сходятся: «14/1» ≠ «14к1», «ул» ≠ «улица», «1 дубровская» ≠ «1-я дубровская» → список пуст во всех 3 fallback-слоях → «Ничего не найдено».
- Симуляция: «1 дубровская ул 14/1» FAIL, «1 дубровская улица 14» FAIL, «дубровская 14» PASS.
- Фильтр в коде с ~1.1.83 (коммит `aa7f6cfc`, 20.08), в релизе 1.1.100 есть — **не связан с последними серверными правками**.
- Кнопка «Карта» в коде есть (`searh_address_widget.dart:667`) и видна на скрине заказчика справа вверху — уточнить, что он имеет в виду.

**Что делать:**
- Смягчить `_titleMatchesQuery`: токенный матчинг —
  - улица: каждый значимый токен запроса ищем подстрокой в title/street с нормализацией («ул»→«улица», «1-я»↔«1 », дефисы);
  - дом: сравнивать по цифровой последовательности («14/1»→[14,1] эквивалентно «14к1», «14с1», «14 к 1»);
  - результат без дома в запросе — матчится по улице как раньше.
- Слои `_attachMapKitCenters` / MapKit fallback используют тот же фильтр — правка одна, покроет все пути.
- **Требует новой сборки МП** — баг в релизе у пользователей.
- Не ломать: фильтр добавлялся против сёл/рек/районов в выдаче — сохранить отсев не-адресов (tags street/house остаются).
